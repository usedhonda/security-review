# security-review

**普段のPR・main更新で、変更されたソースファイルをAIがセキュリティレビューするツールです。公開試験版です。** CodeQLに置き換えたものではなく、このリポジトリの既存AIエンジンを再利用します。

## いま動いているもの

**自動AI検査を導入・実動作確認済みなのは、現在 `usedhonda/security-review` 自身です。** 別リポジトリへの一括導入が完了したという意味ではありません。

このリポジトリで、所有者が同じリポジトリ内のブランチから `main` 宛てにPRを作成・更新すると、**AI security review → Review changed code with AI** が自動で動きます。`main` へのpush・マージ後にも動きます。検査開始のためのWeb操作・Run workflow・読み取りキー・ZIPは不要です。

文書だけの変更では `no_supported_source_changes` と表示し、AIを呼びません。これは脆弱性の検査に合格したという意味ではありません。実際のAI検査を試すときは、普段のPython等のソース変更で確認します。

## 結果

PRのChecksに完了・未完了・指摘件数・費用を表示します。詳細な仮説・元ファイルへのリンク・修正の手掛かりは、**検査を呼び出したリポジトリの Security → Code scanning** に保存します。

このリポジトリの結果は [Security画面](https://github.com/usedhonda/security-review/security/code-scanning) にあります。詳細の閲覧にはGitHubの適切な権限が必要です。自動起動のためにこの画面を開く必要はありません。

未修正の詳細を公開ログ・公開Artifact・PRコメントへ転載しません。PR変更の詳細もdefault branch側の結果一覧に保存し、本文に実際に検査したheadのコミットとファイル位置を記録します。公開PRへの詳細注釈を避ける構成です。合成データによる保存・認証付き読み出し・公開注釈の点検は行いますが、あらゆる公開経路に対する秘密性の保証ではありません。

## 自動検査の範囲と費用

そのPR・pushで変更された対応ソースファイルの現在の全文を調べます。別の3リポジトリを無関係に抽出する処理ではありません。ただし、変更前の全文や変更されていない周辺モジュールは送らないため、完全な前後比較や全リポジトリ監査ではありません。

- 1回最大16ファイル・96 KB・AI生成1回。上限超過、削除されたソースなど未対応の変更、未完了、保存失敗は合格扱いにしません。
- 既定の見積予算は **$0.50/イベント**。月額上限・アカウント全体の請求上限ではありません。PRとそのマージで2回実行される場合があります。
- モデルは既存エンジンの `gpt-6.1-sol`。公式トークン数の事前確認・費用予約・自動再試行なしの制御を維持します。使用量からの計算額と実際の請求額は区別します。
- 試験版の有料PR検査は公開リポジトリの所有者が作成した同一リポジトリ内PRに限定します。Fork・外部投稿者のPRは対象外で、検査済みとは表示しません。

**高確信度のHigh/Critical指摘ではチェックを失敗にします。ただし、mainの変更やマージを禁止するには別途必須チェック等のルールが必要です。この導入では、そのルールは変更していません。** 自動修正・自動マージも未実装です。ChatGPTの接続から権限付きCode scanningの本文を読めない制約も、この変更だけでは解消していません。

## 別のリポジトリで使う場合

共通処理は `.github/workflows/ai-review-reusable.yml` にあります。呼び出し側の短いworkflowから、固定コミットの共通処理を呼びます。実行するエンジンも固定コミットです。対象コードを実行・インストールせず、固定コミットのGit blobをデータとして取得・検証します。

**呼び出し側にも、その利用者の `OPENAI_API_KEY` が利用できる必要があります。** 共通処理を呼ぶだけでは、このリポジトリに登録したSecretは共有されません。作者のキーを他人へ提供するサービスではありません。Fork利用者も自分のキー・API利用予算を使い、呼び出すworkflow/engineの信頼先を確認してください。コードやコメントにはキーを書きません。

`muse-agent-bridge` の呼び出し設定は [下書きPR #20](https://github.com/usedhonda/muse-agent-bridge/pull/20) にありますが、**未導入**です。実行テストで呼び出し側のキーが空だったため、マージしていません。既存キーをこちらで取り出したり再作成したりはしていません。

## 以前からあるアカウント単位の手動検査

こちらも残していますが、上のPR連動検査とは別です。

[Review my public repositories](https://github.com/usedhonda/security-review/actions/workflows/account-review.yml) を手動実行すると、所有する公開リポジトリを自動取得し、未確認を優先して最大3件を選びます。各件最大16ファイル・160 KB、合計$1以内の見積予算・最大3生成です。Fork・アーカイブ・中央ツール自身を除外し、新しい公開リポジトリの個別登録は不要です。前回と同じコミットの選択範囲が完了しているものはスキップします。全ファイル監査ではありません。

このモードだけは中央のキーで中央に結果を保存します。2026-10-31に [3件の実検査](https://github.com/usedhonda/security-review/actions/runs/41227346132) が完了し、使用量から計算した費用は$0.327290でした。以前の「キーが空で未実行」という記載は、その後解消した確認時点の情報でした。

## 旧方式と開発

旧オフラインHTML・age鍵・Security review pilotは互換性のため残しています。新しい通常手順には不要です。[旧レポートの回収](docs/ENCRYPTED_RECOVERY.md)

Python 3.11以上。既存の暗号化互換テストにはage CLIが必要です。

```sh
PYTHONPATH=src python3 -m unittest discover -s tests -v
```

中核は `src/security_review/`、PR/main連動は `scripts/review_event.py`、手動アカウント検査は `scripts/account_review.py` です。
